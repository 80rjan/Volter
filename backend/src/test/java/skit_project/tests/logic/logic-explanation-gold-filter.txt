1. PREDICATES AND CLAUSES
------------------------------------------------------------------------
In .filter for attr goldWeightGrams (p.getItem() != null && p.getItem().getType() == ItemType.GOLD).
Предикат  P = a && b
Клаузи:
    a : item != null

2. TRUTH TABLE
------------------------------------------------------------------------
За P = a && b:
    a го определува P  <=>  b = точно      (тогаш P = a)
    b го определува P  <=>  a = точно      (тогаш P = b)

 ред | a | b | P = a&&b | a активна? | b активна?
 ----+---+---+---------+------------+------------
  1  | T | T |    T     |    да      |    да
  2  | T | F |    F     |    не      |    да
  3  | F | T |    F     |    да      |    не
  4  | F | F |    F     |    не      |    не

Објаснување за „активна":
  - a е активна во редови 1 и 3 (таму b = T): превртувањето на a го превртува P.
    Во редови 3,4 (b = F) превртувањето на a не го менува P (останува F) -> a не е активна.
  - b е активна во редови 1 и 2 (таму a = T): превртувањето на b го превртува P.
    Во редови 3,4 (a = F) b не е активна (P останува F), а во реалниот код b воопшто не се оценува.


3. TEST REQUIRE
------------------------------------------------------------------------
GACC — Општа покриеност на активна клауза (General Active Clause Coverage)
  За секоја клауза, направи ја активна и тестирај ја и точно и неточно; ДРУГИТЕ (споредни) клаузи
  може да земат кои било вредности (и може да се разликуваат меѓу двата реда) сѐ додека главната
  клауза останува активна.
    главна a активна (бара b = T): {a=T,b=T}=ред1 (P=T) и {a=F,b=T}=ред3 (P=F)
    главна b активна (бара a = T): {a=T,b=T}=ред1 (P=T) и {a=T,b=F}=ред2 (P=F)
  GACC TR редови = { ред1, ред2, ред3 }

CACC — Корелирана покриеност на активна клауза (Correlated Active Clause Coverage)
  Исто, но дополнително двата реда за главната клауза мора да направат P да земе РАЗЛИЧНИ вредности.
  Бидејќи активната клауза го определува P, P е автоматски T во едниот ред и F во другиот, па
  барањето е исполнето со истите редови.
    a: ред1 (P=T), ред3 (P=F)   -> P се разликува, ОК
    b: ред1 (P=T), ред2 (P=F)   -> P се разликува, ОК
  CACC TR редови = { ред1, ред2, ред3 }

RACC — Рестриктивна покриеност на активна клауза (Restricted Active Clause Coverage)
  Исто, но СПОРЕДНИТЕ клаузи мора да бидат ИДЕНТИЧНИ во двата реда на главната клауза.
    a главна, споредна b: двата реда бараат исто b; за a да остане активна, b = T -> ред1, ред3
    b главна, споредна a: двата реда бараат исто a; за b да остане активна, a = T -> ред1, ред2
  RACC TR редови = { ред1, ред2, ред3 }

РЕЗУЛТАТ: за овој предикат (конјункција од две клаузи) GACC = CACC = RACC = { ред1, ред2, ред3 }.
Оваа совпадливост е очекувана: кај чиста конјункција секоја клауза е активна само кога другата е
ТОЧНА.


4. ТЕСТ ВРЕДНОСТИ (го задоволуваат RACC, значи и CACC и GACC)
------------------------------------------------------------------------
Мапирани на конкретни договори за залог доставени до summarize():

  ред1 (a=T,b=T): item != null И type == GOLD   -> договорот се брои (грамовите се додаваат)
                  тест: goldItem_predicateTrue_isCounted        (тврди totalGoldGrams > 0)
  ред2 (a=T,b=F): item != null И type != GOLD    -> договорот НЕ се брои
                  тест: nonGoldItem_predicateFalse_notCounted   (тврди totalGoldGrams == 0)
  ред3 (a=F,-)  : item == null (b маскирана)      -> договорот НЕ се брои
                  тест: nullItem_predicateFalse_notCounted      (тврди totalGoldGrams == 0)

дека само златниот придонесува кон totalGoldGrams, додека сите три сепак се бројат во вкупната
главница/камата.
